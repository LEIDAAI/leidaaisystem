# Dianleida Skill · 店雷达 1688 选品引导技能

## 触发条件

用户请求涉及以下任一场景时加载本技能：

- 1688 找商品/选品/找货源/批发
- 查询热销榜/榜单/爆款
- 分析某个商品卖得好不好
- 查看 1688 类目/分类
- 评估供应商/工厂资质
- 商品详情对比
- 图片找货/以图搜货/图片寻源

## MCP 连接器识别（重要）

**本技能所有工具调用必须使用店雷达/dld MCP 连接器，不要用其他 MCP 服务。**

### 识别方式（不要校验工具名）

不要求用户配置的 MCP 服务工具名与本文档完全一致。文档中的工具名仅作辅助参考。识别连接器只查服务名称，不校验工具目录，不要求工具名与文档一致。

**只要当前环境可用的 MCP 连接器名称包含以下任一特征，就认定是店雷达/dld：**

- 包含 "dld"（不区分大小写，如 dld-mcp、dld_mcp、dldmcp）
- 名称发音或首字母与「店雷达」重叠（如 dianleida、dianleidamcp）

当运行时将 MCP 调用表示为 `mcp__<service-name>__<tool-name>` 时，仅检查 `<service-name>` 命名空间来识别连接器。不要求 `<tool-name>` 包含 dld、dianleida 或任何其他连接器关键字。如果运行时单独暴露连接器注册表，则优先检查该注册表。

### 连接器首次握手（强制流程）

1. 从已配置的 MCP 服务/连接器名称匹配店雷达。在检查或过滤单个端点名称之前执行此操作。匹配的服务始终属于店雷达，无论其工具如何命名。
2. 服务名称匹配后，直接调用完成当前任务所需的业务工具（如 `product_search_list`、`product_billboard_list`、`product_info`、`get_category_info`、`image_search`）。识别与调用只查连接器名称，不校验工具目录、不要求工具名与文档一致。dld MCP 已不再提供剩余点数查询接口，不要尝试调用任何用户信息或点数余额类接口。
3. 业务调用返回错误时，先检查错误信息再决定分支：

   - **点数不足**：错误说明点数/余额/配额/额度不足或已耗尽时，立即停止后续业务调用，仅返回以下用户消息（精确输出，不附加注册或配置链接）：

     ```text
     当前您的MCP点数不足，无法使用此服务。请及时充值后重试，充值请点击：https://www.dianleida.net/mcp/buy/
     ```

   - **密钥失效**：错误说明密钥、凭证、token 失效或鉴权失败时，停止后续业务调用，提示用户当前 dld-mcp 密钥已失效，请到店雷达重新获取密钥并在其当前 AI 工具的 MCP 配置中更新后重试。用户重新发来密钥后，按「MCP 密钥配置流程」帮其更新配置。
   - **其他错误**（含工具不存在、服务不可达、无权限等）：先用属于同一服务的另一个可用接口重试一次；仍失败时如实告知用户当前调用失败，不编造数据，也不在服务名称已匹配的情况下声称 MCP 未配置。随后本次会话立即止损：停止把后续业务调用路由到该 MCP，不再反复尝试，并转入引导配置：提示用户重新提供店雷达 MCP 密钥，按「MCP 密钥配置流程」尝试自动配置（名称固定 dld-mcp），无法自动写入时改为提供当前 AI 工具的前端手动配置步骤；配置完成并重新进入会话、用户明确要求重试后才恢复调用。不要通过端点名称重新分类连接器。

4. 如果检查已配置的 MCP 服务/连接器名称后发现没有匹配店雷达/dld 命名规则的服务，不要立即结束。先主动询问用户是否愿意提供店雷达 MCP 密钥，并明确说明：将尝试帮用户自动配置 MCP，MCP 名称固定为 `dld-mcp`；若当前 AI 工具不支持自动写入、配置目录受保护、加密或格式无法确认，则改为提供该工具前端的手动配置流程。

   推荐提示文案：

   ```text
   检测到您还未配置「店雷达」MCP 连接器，暂时无法使用 1688 选品功能。

   如果您已经有店雷达 MCP 密钥，可以发给我。我会尝试帮您自动配置 MCP，名称为 dld-mcp。
   说明：这是一次尝试配置；如果当前 AI 工具的配置目录受保护、加密，或无法确认配置格式，我会改为根据您使用的 AI 工具提供前端手动配置流程。

   获取密钥与配置文档：
   1. 访问店雷达官网注册：https://www.dianleida.net/mcp
   2. 查看配置文档：https://www.dianleida.net/mcp/docs/
   ```

5. 用户同意并提供密钥后，按「MCP 密钥配置流程」处理。用户拒绝或暂不提供密钥时，再输出手动配置步骤，不编造调用或呈现虚构商品数据。

6. 如果已配置店雷达/dld 服务名称但当前任务未暴露该服务的可调用接口，不显示注册或配置文档链接。将连接器视为已配置，告知用户连接器已配置但当前会话未能加载其接口，建议检查连接器启用状态或重新进入会话后再试。

此握手即使用户直接要求已知的店雷达操作也必须执行。输出分支互斥：匹配/已配置的店雷达服务可以显示充值消息但不能显示注册链接；未匹配/未配置的服务可以主动请求密钥并尝试配置，但不能显示充值链接。不要在一条回复中合并两个分支。

### MCP 密钥配置流程

当用户在未配置 MCP 的场景下提供店雷达 MCP 密钥，或用户主动发来店雷达 MCP 密钥时，按以下方式响应：

1. 先告知用户：将尝试在当前 AI 工具中自动配置店雷达 MCP，MCP 名称固定为 `dld-mcp`。同时说明不同 AI 工具配置方式不同，若配置目录受保护、加密或无法确认配置格式，可能无法自动写入。
2. 自动配置时使用以下标准配置条目（`url` 即用户发送的密钥 URL，其余字段固定不变）：

   ```json
   {
     "mcpServers": {
       "dld-mcp": {
         "url": "用户发送的密钥url",
         "transport": "http",
         "disabled": false
       }
     }
   }
   ```

3. 尝试配置前不要向用户复述完整密钥。只在必要时使用密钥写入配置；不要写入记忆文件或日志。
4. 如果能明确识别当前 AI 工具的 MCP 配置文件位置、格式，且文件可写，则备份原配置后写入 `dld-mcp` 配置。写入后提示用户重启或刷新 MCP 连接器，再重新提问使用。
5. 如果不能明确识别配置位置、配置目录受保护、配置文件加密、写入失败或权限不足，不要继续猜测路径，也不要声称配置成功。改为输出手动配置流程：

   ```text
   我尝试帮您自动配置 dld-mcp，但当前环境无法安全写入 MCP 配置。可能原因是配置目录受保护、配置文件加密，或当前 AI 工具不开放自动写入。

   请按当前 AI 工具的前端流程手动配置：
   1. 打开 MCP / 工具 / 连接器管理页面
   2. 新增 MCP 服务器
   3. 名称填写：dld-mcp
   4. URL 填写您的店雷达 MCP 密钥 URL
   5. Transport 选择：http
   6. 启用该连接器并保存
   7. 重新进入会话或刷新工具列表后再提问
   ```

6. 配置成功后，如果当前会话仍未加载新接口，告知用户需要重新进入会话或刷新 MCP 工具列表；不要立即编造商品数据。

## 意图识别

在选择字段或展示方式之前，先分类用户意图：

- **商品意图**：包括商品搜索、选品、排名、详情、对比、分类、供应商、采购、价格、销量、库存和商品图片。
- **服务/账户意图**：包括点数余额、配额、权限、任务状态、配置或其他非商品信息。
- **混合请求**：将答案分为意图特定的部分，避免添加无关的商品卡片。

## 场景识别（先识别，再执行）

```
用户提到 1688/选品/批发/找货？
├─ 有商品链接/ID → product_info（直接调用）
├─ 提到排行/热销/榜单 → product_billboard_list（直接调用）
├─ 提到类目/分类 → get_category_info（直接调用）
├─ 提供图片 URL/Base64/Data URI 或提到以图搜货/图片找货 → image_search（直接调用）
├─ 有商品关键词（手机壳/女装等）→ product_search_list（直接搜索）
├─ "帮我找好卖的"无品类 → 只问1个问题：想找哪个品类？
└─ 其他模糊请求 → 只问1个问题确认方向
```

**关键规则：命中即执行，不要反复确认。** 只要用户给了任何关键词，立即搜索。只有完全无方向时才追问，且只问1个问题。场景路由中的「直接调用」以握手通过为前提：连接器名称已匹配即调用；调用失败时按握手错误分支止损，不继续把后续业务路由到该 MCP。

## 默认参数（用户未指定时自动推断）

**通用默认：** pageSize=20, pageIndex=1, sortType=desc, cycle=7, sortField=orderCount7d

**数量规则（列表类工具，强制）：**

- 适用工具：`product_search_list`（商品搜索）、`product_billboard_list`（热销榜单）、`image_search`（图片寻源）
- 用户没有说明调取数量时：pageSize/limit 默认取 100（接口单次返回上限），并默认展示全部返回的商品，不要只展示前 20 条；查询命中的商品总量确实大于 100 时取上限 100 条，总量不足 100 时有多少展示多少，不强凑数量
- 用户明确要求数量时：必须严格按用户要求的数量设置参数获取，并按该数量展示，不得擅自增减
- 其余工具（`product_info`、`get_category_info` 等非列表工具）不受此规则影响，仍按通用默认

| 用户表达 | 推断参数 |
|----------|----------|
| "好卖的""爆款""热销" | sortField=orderCount7d, cycle=7 |
| "最近火的" | sortField=orderCount7d, cycle=7 |
| "长期稳定卖的" | sortField=ordersCount |
| "便宜的" | sortField=price, sortType=asc |
| "高端的""贵的" | sortField=price, sortType=desc |
| "新品" | offerType=2 |
| "1688严选" | offerType=3 |
| "跨境" | offerType=4 |
| "支持定制" | offerType=5 |
| "工厂直供""源头工厂" | companyType=2, shiLiType=["superFactory"] |
| "一件代发" | proxyRights=["4360897"] |
| "发货快" | sendTime=[24,48] |

> **注意：** 当前搜索工具 cycle 仅使用 7 或 30；sortField 时间维度必须与 cycle 一致（cycle=7 → orderCount7d；cycle=30 → orderCount30d）。

其他常用可选参数：keyWord（关键词）、beginPrice/endPrice（价格区间）、beginOrderCount（最低销量笔数）、beginSaleCount（最低件数）、location（地域，如[{"province":"广东"}]）。

## 默认商品展示

对于商品意图，默认生成独立的、响应式的 HTML 商品页面，使用 MCP 返回的真实商品图片，然后在聊天中提供生成的 HTML 文件链接。不要默认使用表格截图、装饰图片、纯 Markdown 表格或聊天内嵌商品卡片，除非用户明确要求该格式。页面中的商品图片必须通过 `<img src>` 直接加载 MCP 返回的商品主图线上地址进行展示，尽量不要往用户本地下载图片；仅当用户明确要求把图片保存到本地时才下载。

### 列表结果工作流（强制）

对于 `product_search_list` 和 `product_billboard_list`，将列表响应本身作为主要商品来源。文档化的响应包括：

- `image`：商品图片 URL；当非空时将其渲染为商品卡片图片。
- `goodsUrl`：商品链接；当非空时将其渲染为可点击的商品链接。
- `offerId`：商品标识符；需要时保留用于后续详情调用。

收到商品列表后，在编写答案之前映射每个返回项。不要丢弃 `image` 或 `goodsUrl` 而使用表格。只有当用户询问列表未提供的详情字段、缺少必需字段或需要进行单品分析时，才调用 `product_info`。不要仅为获取列表中已有的字段而调用它。

### 图片寻源工作流（强制）

对于 `image_search`，当用户提供图片 URL、纯 Base64、`data:image/...;base64` 图片，或明确表达“以图搜货/图片找货/图片寻源/找同款”时直接调用。请求格式固定为：

```json
{
  "req": {
    "imageUrls": ["图片地址或Base64"]
  }
}
```

执行规则：

1. `imageUrls` 必须包含 1 至 5 项；超过 5 张时先说明一次最多处理 5 张，并让用户选择或默认取前 5 张。
2. 每项可为 HTTP(S) 图片地址、纯 Base64，或 JPEG/PNG/WebP Data URI。
3. 如果用户上传的是本地图片，优先在当前环境可行范围内转换为可用图片地址或 Base64；无法读取或转换时，只问用户补充图片 URL 或重新上传图片。
4. 结果按“原图 → 候选商品列表”分组展示，优先展示商品图、标题、价格、销量、商品链接、相似度/匹配说明（如返回中存在）。
5. 不要把 `image_search` 返回的候选商品再无条件交给 `product_info`。只有用户要求单品趋势、列表缺少关键字段，或需要深度分析某个候选商品时，才使用候选项的 `offerId` 调用 `product_info`。
6. 若图片寻源无结果，如实说明未找到候选商品，并建议用户换更清晰、主体更完整的商品图。

### 意图驱动的链接选择

在生成任何 HTML 页面或内嵌卡片之前，先分类用户要查看的内容：

1. **明确商品意图**（商品、产品、单品、爆品、榜单商品、商品详情、商品对比、选品）：当可用时使用商品的精确 `goodsUrl` 作为商品链接。如果 `goodsUrl` 缺失但存在有效的 `offerId`，构造 `https://detail.1688.com/offer/{offerId}.html`。仅在需要额外详情或需要验证 ID/链接时使用 `product_info`。不要用店铺 URL 替代。
2. **明确店铺/供应商意图**（店铺、供应商、商家、工厂、公司、店铺链接）：当可用时使用返回的店铺/供应商/公司 URL。不要在以店铺为中心的回答中强行使用商品链接。
3. **混合意图**：在商品项上显示商品链接，在供应商/店铺部分显示店铺链接，带清晰标签。
4. **非商品意图**（点数、额度、权限、任务状态、配置）：除非用户要求，否则省略商品图片和商品/店铺链接。
5. 如果相关商品链接缺失，首先从有效的 `offerId` 派生 `https://detail.1688.com/offer/{offerId}.html`；只有当 `goodsUrl` 和有效的商品 ID 都不存在时才说明不可用。不要编造 ID 或静默替换链接类型。

链接检查适用于每一轮，但所需的链接类型由用户意图而非全局固定。

当 `image` 存在时，将其包含在默认 HTML 商品卡片中。仅当结果为非商品数据或用户明确要求表格时才允许使用普通表格。仅当用户明确要求聊天内嵌显示、内嵌预览或不要 HTML 页面时才允许使用聊天内嵌商品卡片。

对于每个商品，只要 MCP 提供以下三个核心字段，就使用它们：

1. 商品名称
2. 商品主图
3. 商品链接

精确识别文档化的字段名（`image`、`goodsUrl`、`offerId`），同时也容忍连接器返回的等效大小写变体（`imageUrl`、`mainImage`、`productUrl`、`productId`）。对于商品意图，优先使用 `goodsUrl` 或等效的单品 URL；当缺失时，从有效的 `offerId` 派生 `https://detail.1688.com/offer/{offerId}.html`。对于店铺意图，仅当匹配该意图时才使用连接器的店铺/供应商/公司 URL。保留返回的 URL，不要编造或交叉替换 URL 类型。

仅当用户的问题需要或当它们实质性地澄清结果时才添加其他字段，如价格、销量、分类、起订量、供应商、评分或物流信息。保留 MCP 的实际值和 URL。

在交付默认 HTML 页面链接后，附加简短说明：`还可以继续为你生成聊天内嵌样式哦。`

## 非商品响应

对于服务/账户意图，仅回答该问题所需的字段。除非用户要求，否则不包含商品名称、商品图片或商品链接。用户询问剩余点数时，说明 dld MCP 已不再提供点数余额查询接口，点数余额可在店雷达官网（https://www.dianleida.net/mcp/）查看；点数不足时业务接口会自动提示。

## HTML 和聊天内嵌模式

对于商品或店铺意图，默认生成 HTML 页面；当用户要求 HTML、页面、仪表板、目录或可分享视图时也生成 HTML 页面。在写入文件之前执行意图驱动的链接检查；对于商品卡片，首先解析 `goodsUrl` 并在需要时从 `offerId` 派生 1688 详情 URL。使用与请求相关的链接类型。使其独立、响应式且无需构建步骤即可使用，除非要求使用框架。验证桌面和移动端布局，然后提供文件链接。

仅当用户明确要求 `聊天内嵌`、`直接展示`、`内嵌样式`、内嵌预览或以其他方式拒绝 HTML 时，才使用聊天内嵌商品卡片。渲染真实商品图片、商品名称和 `goodsUrl` 商品链接；仅添加与用户问题相关的字段。

## 结果展示规范（强制）

1. **5项信息不可省略：** 商品图片、标题、批发价、销量（笔数/件数）、商品链接（`https://detail.1688.com/offer/{offerId}.html`）
2. **展示形式：** 1-5个用HTML卡片或Markdown卡片；6-20个用表格（含图片缩略列）；20+用精简表格（前几个带图）
3. **单品分析：** 顶部商品图+基础信息，下方表格展示每日趋势（日期/笔数/件数/销售额/价格），底部给出趋势解读
4. **数据解读必须给出：** 概览（找到多少款、价格区间）、亮点（某商品销量突出）、下一步建议（是否需要细化筛选/深入分析）
5. **HTML需渲染输出**，不要包裹在代码块中

## 预览和澄清

如果用户要求预览，先显示少量代表性内嵌商品卡片并等待确认后再生成完整 HTML 页面。如果用户明确要求不同格式，则遵循该请求。否则，对商品意图使用 HTML 页面默认值。

## 交付规则

- 保持输出字段由用户问题驱动，而非固定架构。
- 对于具有非空 `image` 的商品结果，当检测到商品意图时，渲染图片、名称和已解析的商品链接为 HTML 商品卡片。按以下顺序解析：`goodsUrl` -> 等效商品 URL -> `https://detail.1688.com/offer/{offerId}.html`。对于店铺意图，改为渲染相关的店铺/供应商链接。
- 默认 HTML 结果后，始终包含：`还可以继续为你生成聊天内嵌样式哦。`
- 在交付之前，检查生成的 HTML 并确认每张卡片使用检测到的意图所需的 URL 类型；不要在非商品或仅店铺结果中要求商品链接。
- 对生成的本地工件使用绝对路径，并在客户端支持时内嵌渲染图片。
- 尽量不要往用户本地下载图片：生成 HTML 页面或聊天内嵌卡片时，商品主图一律直接使用 MCP 返回的 `image` 线上地址加载展示，不要先下载到用户本地再引用；仅当用户明确要求保存图片到本地时才下载。
- 不要暴露临时文件或编造缺失的商品数据。

## 版本检测与自动更新（技能加载时执行）

**每次技能被触发时，在执行业务逻辑之前先执行版本检测。** 检测失败不阻断技能使用。

### 检测流程

1. 读取本地 `manifest.yaml` 的 `version` 字段，获取本地版本号 `local_version`
2. 读取 `manifest.yaml` 的 `update_strategy.version_check_url`，获取线上版本检测地址（`https://obs.dianleida.net/skills/version.json`）
3. 请求该地址获取 `version.json`，提取 `version` 字段为 `remote_version`，提取 `download_url` 为 ZIP 下载地址
4. 比较 `local_version` 与 `remote_version`（语义化版本比较，按 MAJOR → MINOR → PATCH 依次对比）

### 检测结果处理

| 比较结果 | 行为 |
|----------|------|
| `local >= remote` | 版本一致或本地更高，跳过更新，直接执行技能正常流程 |
| `local < remote` | 向用户展示更新提示，等待用户确认 |
| 检测失败（网络超时/地址无效/格式异常） | 静默跳过，直接执行技能正常流程，不向用户报错 |

### 更新提示

当 `local < remote` 时，向用户展示：

```
检测到「店雷达技能」有新版本：
  当前版本：v{local_version}
  最新版本：v{remote_version}
  更新内容：{version.json 的 changelog_highlight，无则省略此行}

是否立即更新？
```

### 用户确认更新后执行拉取

1. **备份**：将当前技能包所有文件复制到 `_backup/v{local_version}/`
2. **下载 ZIP**：从 `version.json` 的 `download_url`（`https://obs.dianleida.net/skills/dld-mcp-skill.zip`）下载最新技能包 ZIP 到临时目录
3. **解压覆盖**：将 ZIP 解压，覆盖本地技能包目录下所有文件
4. **验证**：检查 `manifest.yaml` 的 version 已更新、SKILL.md 存在且非空、references 目录完整
5. **验证通过**：告知用户「技能已更新至 v{remote_version}」，清理临时 ZIP，继续执行技能流程
6. **验证失败**：从 `_backup/v{local_version}/` 恢复全部文件，告知用户「更新失败，已恢复至 v{local_version}」

### 用户拒绝更新

直接使用当前版本执行技能正常流程，不再追问。

### 注意

- 版本检测应在技能加载时一次性完成，不要在业务执行中途插入
- 检测请求应设置合理超时（建议 3 秒），超时视为检测失败
- 拉取文件前必须先备份，确保可回滚
- 不要因版本检测失败而阻止用户使用技能

完整规则、version.json 格式、提示规范见 [更新策略](references/更新策略.md)。

## 注意事项

1. **只查名称，失败止损并引导配置** — 识别连接器只查服务名称，不校验工具目录、不要求工具名与文档一致，名称匹配即直接调用；非点数/鉴权类调用失败时按握手分支重试一次，仍失败则本次会话停止把后续业务路由到该 MCP，并引导用户按「MCP 密钥配置流程」重新配置
2. **搜索优先，追问最后** — 有关键词就搜索，只有完全无方向才问1个问题，严禁连环追问
3. **图片不可省略** — 每次展示商品必须带图片
4. **数据解读必给** — 展示原始数据外必须给出概览/亮点/建议
5. **榜单日期** — 当前榜单工具支持周榜/月榜：pageType=2 传周榜且 date 为周日，pageType=3 传月榜且 date 为月初，格式 YYYY-MM-DD
6. **点数** — 每次调用消耗1点；点数不足时业务接口直接返回点数不足错误，返回充值提示即可（无点数查询接口）
7. **密钥安全** — 用户提供的 MCP 密钥只用于写入配置，不复述、不记录到记忆或日志
8. **点数保护** — 每轮新会话的第一次对话先读取 `point-protection.md`：业务工具调用成功每次计 1 点，单轮问答满 10 点先中断询问用户是否继续，结束后披露各工具调用次数与点数
