# 点数保护规则（强制）

> 本文件为独立附加规则，不修改技能包内其他文档；与 SKILL.md 同目录随包分发，AI 执行店雷达 MCP 相关任务时必须同时遵循本文件。

## 背景

店雷达 MCP 的业务工具调用会消耗用户点数（用户花钱购买），频繁调用既损害用户利益，也会对服务器造成压力。因此必须控制调用频次、复用已查数据、并保持消耗透明。

## 计费口径

- 店雷达 MCP 共 5 个业务工具：`get_category_info`、`product_search_list`、`product_billboard_list`、`product_info`、`image_search`，**每次调用成功计 1 点**（仅统计 MCP 正常返回数据的调用；AI 发起调用但 MCP 返回失败/报错的调用不扣点、不计入计数）。
- 识别连接器的"握手"（查看可用连接器列表）不是业务调用，不扣点、不计入。

## 规则一：已查数据复用

- 同一会话内，之前任何轮次调用工具获得的数据都可以继续使用，不得视为过期。
- 相同或近似条件的查询：直接复用已有结果作答，**不再调用接口**。
- 用户追问筛选、排序、对比、解读：优先在已有结果集上处理，不重新调用。
- 仅当已有数据确实无法覆盖当前需求（新关键词、新类目、新数据维度）时，才发起新调用。

## 规则二：10 点熔断

- 计数范围：单轮问答（用户一次提问到本轮回答结束）。
- 当本轮已消耗 10 点、且任务还需要继续调用工具时，**必须中断当前任务**，明确告知用户"本轮已消耗 10 点"，并询问是否继续。
- 用户选择不继续：直接基于已获得的记录返回结果，正常收尾，**不得再调用任何业务工具**。
- 用户选择继续：继续查询；此后每再消耗满 10 点，同样中断询问一次。

## 规则三：消耗披露

- 每轮回答结束后，必须告知用户本轮调用了哪些工具、每个工具的调用次数及对应点数。
- 披露格式示例：`本次共调用 3 次、消耗 3 点：商品搜索 ×2（2 点）、商品详情 ×1（1 点）`。
- 本轮一次业务工具都没调用时，无需披露。

## 注意

- MCP 返回失败（报错）的调用不扣点、不计入熔断计数；重试后成功的调用正常计 1 点。
- 触发熔断询问时，无论用户如何选择，都不得隐瞒已发生的消耗。
