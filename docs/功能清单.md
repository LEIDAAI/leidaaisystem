## 2. 后台功能清单（运营管理端，16 个菜单）

> 登录后按权限动态可见菜单；无权限访问路由跳 403；未知路由跳 404。会话有过期时间（mock TTL）。

### 2.1 登录/会话
- 账号密码登录、会话恢复（刷新不掉线）、登出、登录后跳转原目标页（redirect）。
- 路由守卫：菜单按 `meta.perm` 权限过滤；无 dashboard 权限时自动落到第一个有权限的页面。

### 2.2 仪表盘（dashboard:view）
- 指标卡：用户数 / 订单数 / 收入 / 会话数。
- 7 日趋势图、套餐分布、专家会话量排行、最近注册用户、最近订单。
- 验证要点：与用户/订单列表页数字口径一致；无权限用户不可见。

### 2.3 用户管理（user:view / user:ban / user:entitlement）
- 列表筛选：关键词（手机号/ID）、状态（正常/封禁）、注册时间区间；分页。
- 详情抽屉 6 个 Tab：基本资料、套餐权益调整、订单列表、对话统计、对话记录、登录日志。
- 封禁（已封禁用户无解封入口，传 false 请求拒绝）：**必须填写原因**，留痕审计日志。
- 套餐权益调整：手动改用户套餐/权益（权限点 user:entitlement）。

### 2.4 订单管理（order:view / order:create / order:remark / order:export）
- 筛选：订单号、用户 ID、状态（待支付/已支付/已关闭）、支付渠道（微信/支付宝/线下录入）、下单时间区间。
- 列表列（R5）：订单号、用户 ID、用户手机号、微信昵称、套餐、订单来源（线上/手工/赠送 三色标签）、到期状态、剩余积分、套餐时长（含「长期有效」）、近 7 日消耗、商品金额、优惠金额、实付金额、状态、支付时间、下单时间、到期时间、备注、操作；超宽横向滚动。列表已移除渠道列，渠道筛选、详情支付流水及 XLSX 的支付渠道信息保留。
- 用户手机号按 userId 关联当前用户 phone（脱敏原样，查无 `—`）。详情与 XLSX 同步三项新字段；XLSX 保留既有导出列序及支付渠道，一次导出固定 now。
- 到期展示：PENDING/CLOSED 为「未生效」且时间 `—`；PAID 明确长期（0 月或 0 天、expiresAt=null）显示「长期有效」；有限到期前显示「未到期 ceil((expiresAt-now)/86400000)天」，相等及之后显示「已到期 ceil((now-expiresAt)/86400000)天」，刚好到期为 0 天；缺失/非法值显示 `—`。列表/详情共用每分钟刷新的单一时钟，卸载清理。
- 到期存储：订单级 expiresAt（现有 dayjs 时间约定）；新手工单保存创建时精确 durationDays 快照，paidAt 加天数计算；新赠送单 paidAt 加实际选定日历月（月底收敛）。长期为 null。v17 存量只补无 expiresAt 字段的数据：历史月数用历史 paidAt 加日历月作演示回填，不读取当前套餐、不覆盖已存在值、不重置用户数据。订单展示不代表用户权益发放，TC-39 仍不回写用户套餐/到期。
- 操作：详情抽屉（含支付流水）、备注（留痕审计）。
- 创建手工订单：按手机号+常规套餐下单，AI 积分始终置灰不可点击，未选为 0，选择/切换立即带出当前套餐 credits（含 0），提示积分来自当前套餐不可修改；金额默认带出售价且可微调、不可为负。R6：提交及 mock 服务端均以当前套餐积分为准，服务端验证套餐存在、启用且为常规后读取积分，忽略客户端 credits；兼容保留 payload 字段，不新增真实后端。
- 创建赠送订单（R9）：按手机号+赠送套餐下单；长期有效锁定 0 月，会员模式锁定「会员期内有效」且 durationMonths=null，不显示 1–36 月；自定义仍默认 N 月（1–36 可调）。模式由服务端套餐配置决定，忽略客户端到期字段，NONE/EXPIRED/UNKNOWN 拒绝 422。备注 ≤200 字，赠送积分可改。
- 用户于 2026-11-05 确认跟随会员期：会员续费赠送继续有效，到期失效。会员订单仅记录 MEMBERSHIP 模式，不固定到期；每次列表/详情/XLSX 查询由 readMockMembership 动态返回 expiresAt、membership（source=MOCK，ACTIVE/EXPIRED/NONE/LIFETIME/UNKNOWN）。到期显示已到期N天，无会员显示会员已失效/—，未知显示—，长期会员显示会员期内有效（长期会员），不能误判赠送独立永久化。列表/详情/导出共用解析，历史补值跳过会员模式。
- 单一模拟会员源为持久化的 `MockUser.membershipExpireAt:string|null`、`membershipIsLifetime` 及明确付费计划；用户列表/详情 expireAt 与会员订单同源。v17 数据仅在字段缺失时一次性按旧注册+1年口径补值（历史演示回填非真实权益），保留已有字段（含 null）和旧显式 mockMembership 值，不重置用户。读取不再依赖注册日期；免费版 null 为无会员、付费版 null 为未知，均拒绝新会员赠送单；终身必须显式标记，无内置真实终身会员来源。更新单一会员记录并重新查询后跟随新到期；页面每分钟时钟只更新倒计时，需重新查询列表/重开详情获取最新会员源。无真实会员续费接口；真实会员联调、续费/退款/积分回收待接入；创建不回写用户权益（TC-39）继续保留。C端仅透传配置，会员模式消费尚未接入；独立前台未修改。
- 导出 XLSX（R8）：按当前筛选条件导出全部命中订单（非当前页），单表「订单列表」，真正 OOXML `.xlsx`；保留既有 19 列和顺序，权限仍为 order:export。订单号/手机号及用户输入以文本存储，保留前导零、中文、逗号、换行和公式样式原文且不生成公式；用户ID、剩余积分、近7日消耗为整数，商品/优惠/实付金额为数值两位小数。支付/下单/有限到期时间为完整 `yyyy-mm-dd hh:mm:ss` 文本（缺失/非法为 `—`，长期有效保持原语义），时间列宽 25，避免 Excel 窄列显示 `####`。
- 后台全部实际表格导出（订单、单会话）统一使用 `src/utils/excel.ts`，按参考文件采用绿色 `#00A83E` 表头、白色加粗微软雅黑、白/浅绿 `#E9F7EE` 斑马纹、`#BFE7CB` 细边框、26 表头行高、按内容调整数据行高、冻结首行和自动筛选；订单号列宽 28、手机号 18、备注 40 并换行。空结果仍保留表头。专家/技能配置 JSON、技能 ZIP、会话 JSON 和分析 HTML 保持原格式；技能统计没有表格导出入口。

### 2.5 套餐管理（plan:view / plan:edit）★核心模块
- R10 统一入口：类型顺序为常规套餐 / 积分包套餐 / 赠送套餐，可筛选；全部视图中会员套餐与积分包分表展示。积分包复用 `/credit-packages`，不写入 `/plans`，两个数据源 ID 即使相同也分别走对应 CRUD。会员套餐保留时长、版本、引用保护；积分包没有版本/刷新/恢复。
- 新建选择积分包后切换固定包表单；字段为名称、积分、赠送积分、售价/划线价、角标、排序、状态、内部备注。编辑类型锁定，不显示会员周期、会员时长、权限或权益派生。保存后本页与原积分加油包入口同源一致。
- 新建/编辑抽屉（表单分组）：
  - **基础**：名称、唯一编码（创建后不可改，仅字母数字下划线短横线）、启用/上架、套餐类型（常规/积分包/赠送，创建后不可改；以下会员字段仅常规和赠送使用）。
  - **营销信息**（仅常规套餐）：营销标语 tagline、角标 badge、卖点列表 features（一行一条）。
  - **价格**：基础价/划线价；赠送套餐价格锁定 0 元。
  - **计费周期**：月付/年付两行，价格留空=不启用该周期；可配划线价；两个周期全空=仅基础价。
  - **AI 积分**：credits 数值；发放方式 grantMode（一次性/按月）；积分有效期 creditExpiry（永不过期/自定义天数）；赠送套餐固定 0 分、一次性、永不过期。
  - **套餐时长（R9）**：常规支持按天数（含快捷档）/长期有效；赠送支持长期有效、自定义天数、第三单选「会员期内有效」。durationMode 独立存 LIFETIME/CUSTOM_DAYS/MEMBERSHIP，会员模式清空 durationDays；NORMAL 会员模式拒绝 422。旧无 mode 按 day0→长期、其余→自定义，旧长期不混会员。列表显示会员期内有效；保存重开正确回显；白名单、校验、版本快照及 restore 均支持，恢复旧版本显式归一模式、清除残留。
  - **排序**：sort 数值。
  - **前台权限** frontendPerms：按功能组勾选前台可见功能（支持整组全选/取消）。
  - **权益派生展示**（只读折叠面板）：专家/技能/知识库/MCP 四组，展示每项资源对本套餐的可见性标签（全员可见/本套餐可见/指定套餐可见/私有）。
- **保存即发布**：表单校验 → 版本确认弹窗（默认时间戳版本名可改 + 变更说明）→ 写库并生成版本快照，版本号 +1。
- **版本管理**：查看历史版本列表、版本详情（变更前后快照 diff）、**恢复到历史版本**。
- **刷新生效**：配置修改后需点「刷新」才对前台生效（配置快照机制）。
- 删除保护：被引用的资源不可删除。

## 5. 关键业务规则速查（测试断言依据）

1. **长期有效语义**：任意套餐 `durationDays = 0` 即长期有效（不再限于赠送套餐）；后台列表、订单时长均显示「长期有效」；赠送订单 `durationMonths = 0`。
2. **赠送套餐约束**：价格必须 0 元、AI 积分锁 0、类型创建后不可改。
3. **常规套餐校验**：价格非负；有效天数为 0 或正整数；计费周期价格留空=不启用。
4. **手工订单**：选择/切换套餐后自动带出该套餐积分与售价（含 0）；积分置灰锁定不可修改，金额可微调且不可为负；mock 服务端忽略客户端 credits，按已验证的启用常规套餐积分保存。
5. **赠送订单**：长期有效套餐锁定时长；普通套餐默认 = 天数/30 向上取整，1-36 个月内可调。
6. **版本快照**：每次保存配置生成快照并版本 +1，可恢复历史版本；恢复后需刷新生效。
7. **配置生效机制**：所有配置保存后必须「刷新」才对前台生效。
8. **删除保护**：被套餐/其他资源引用的专家/技能/MCP 等不可删除。
9. **审计留痕**：套餐保存、订单创建/备注、用户封禁/权益调整等操作写入审计日志（before/after）。
10. **权限双端校验**：前端隐藏按钮/拦截路由，mock 后端同步返回 403。

## 8. 购买与退款规则方案（建议待确认，未实现）

独立评审入口：https://leidaai.github.io/leidaaisystem/feature-spec.html#transaction-rules 。源文档：https://github.com/LEIDAAI/leidaaisystem/blob/master/docs/功能清单.md ，HTML 源稿：https://github.com/LEIDAAI/leidaaisystem/blob/master/docs/feature-spec.html 。本节为产品建议，不是开发授权、已实现能力或退款法律承诺；不增加现有 178 PN / 104 TC 计数。R10 仅完成积分包配置入口等原范围；现有退款已按要求移除，订单仍只有待支付/已支付/已关闭，TC-38 保留。建议重新引入人工退款，但本次不修改页面业务、接口或数据。

### POL-01 会员时间轴与商品边界

**功能名称：** 单账户会员时间轴与独立积分资产。

**逻辑说明：** 一账户只有一条有序、不重叠的付费会员时间轴，当前有效段与未来已付款预约段分开记录；等级使用显式 rank 比较，不能按价格排序，免费版不是付费会员，月付/年付只是周期而非等级。积分以来源订单的独立批次管理；积分包、赠送包均不提升会员等级，积分包也不改变会员到期时间。不能用 orders.status=PAID 或某订单 expiresAt 推断用户当前会员；按会员段和生效时刻查询。商品类型 MEMBERSHIP/CREDIT_PACKAGE/GIFT 与订单来源 ONLINE/MANUAL/GIFT 分开，手工录入也可有真实实付，赠送及 0 元无现金可退。

统一服务端时钟，时区 Asia/Shanghai，接口携带时区或偏移，区间为 [startAt,endAt)，开始包含、结束不含；终身以明确标志和空 endAt 表达，不能把未知到期当终身。按天为明确 N×24 小时，按月为日历月、按年为日历年；目标月没有原日期则收敛至月底，保留时分秒。每个新段从其 startAt 加购买周期计算；同一年度内按月发放的边界从该年度段原始起点加 k 个日历月计算，避免逐月收敛漂移。

### POL-02 首购、续费与预约降级

**功能名称：** 支付后生效、同级续费及高版本未到期购买低版本。

**逻辑说明：** 免费/已过期且无未来排期可买任意等级，支付成功后生效；有排期则仍须按整条时间轴报价。无未来队列的同级续费从 max(当前到期,支付成功时刻) 顺延；有队列时新增续费一律排在队尾，不能插到当前段后挤掉其他已付费段。报价和支付均展示完整队列、新单首个 start/end 及权益快照；支付成功状态不等于延期段已生效。

推荐结论：高级未到期可以买低级，但仅预约降级，排在当前已付费权益及所有已有预约段结束后生效，不立即降级、不抵扣高等级余额，默认不提前发下期积分。月/年价不能当等级比较。备选简化政策为“高等级到期前完全禁止购买低等级”，待 PM 取舍。终身或无确定队尾时不能给出有限预约日期，转人工，不收取无确定履约时间的预约款。

未生效预约订单取消可退该订单全部实付，撤销未来发放，并追回该订单可用且未消费赠品；若曾异常提前赠送且已消费，转人工风险审批，不负扣。取消后其他已付款段保留原 start/end；出现空档回免费，可另申请提前生效，不能静默前移。

### POL-03 多等级排期与即时升级报价

**功能名称：** 仅升级当前段并保护未来队列。

**逻辑说明：** 报价前重算并展示旧/新整条排期；即时升级只替换当前有效段，保留该段 endAt，未来段原顺序、start/end、价格及权益 snapshot 不变；显示升级后回落日期、回落等级和后续排期。无后续段则到期回免费。所有未来订单保留购买时不可变价格/权益快照，不按后续改价重算；退款单独核算。

等效同期限报价：本期原始实付净额 P_old 为本段累计原始付款及既有升级补款减已处理成功退款后的可归属净额；处理中退款占用须先解决，不能重复抵扣。r=clamp((end−now)/(end−start),0,1)，start/end 为本段原始完整期限，升级不能重置分母。V_old=P_old×r，P_target 为服务端当前有效的目标同期限完整售价，V_target=P_target×r；补差=roundHalfUp(max(0,V_target−V_old),2)，金额按分计算并只在最终补差四舍五入。仅目标 rank 更高才可升级；若补差为 0，仍须明确展示 0 元升级并审计，不能伪造现金付款。连续升级保留本段付款归属链，旧段被替代后不得独立再退款。

不同周期、无等价售价、终身会员不能自动套比例，走客服专项报价审批；无实际生效及无付费对价的赠送会员不得抵现。报价带有效期、价格版本、时间轴版本；支付时若过期或时间轴变化，重新报价并由用户确认，不沿用失效差价。

### POL-04 积分包购买与自定义充值

**功能名称：** 固定包及统一单价自定义积分包。

**逻辑说明：** 固定充值包在支付确认后即时一次性到账独立购买积分批次，附赠积分另建零现金批次，两者关联同订单。自定义购买必须满足 quantity=min+n×step、n 为非负整数且 quantity≤max，服务端校验 min/max/step 与统一单价，金额=roundHalfUp(统一单价×数量,2)，前端预览不替代后端报价。

后台统一单价配置与独立前台演示阶梯价当前未对齐，需前台接入后统一。本建议不把截图 90000 积分／855 元固定为规则或默认价。配置入口已实现不表示真实购买、支付、到账或退款已实现。

### POL-05 积分有效期、发放与升级补发

**功能名称：** 按来源独立过期与生效期发放。

**逻辑说明：** 建议付费积分包自到账时起 365 天有效（与截图一致，仍待确认）；是否另允许永久模式由产品决定，expiresAt=creditedAt+365×24 小时，边界不含。续费不延长任何历史积分包批次。会员套餐积分跟随其发放期结束：一次性积分在会员段生效时发、到该段结束；按月积分在每个实际生效月周期发、到该月周期结束，不预发未来月份；延期订单不提前发。按月调度和真实发放任务尚未实现。

“会员期内有效”赠送已由用户确认跟随会员源续费延长，会员结束则失效；这条沿用 R9 现有 mock 动态查询逻辑，不改成固定 365 天。固定天数及永久赠送独立管理，不跟随续费；赠送包不提升会员等级。

升级积分建议可配置：本发放周期补发=max(0,目标本周期额度−该周期已发套餐额度)，以发放账本累计额度为基准，不用当前余额，不乘 r；提供即时本期服务是该政策理由，不能表述成既有实现。连续升级扣除本周期累计已发套餐及升级额度，避免重复补发；旧批次和已消费不回收、不重置余额，新补批次到当前发放周期结束。若当前段仍有下月则按目标档发，下段恢复预约等级及其 snapshot。

### POL-06 积分耗用与返还

**功能名称：** 最早到期扣减与原批次返还。

**逻辑说明：** FEFO：最早到期先用，永久在最后；同到期先不可退款赠送、再付费、再按创建时间（仍同序用批次 ID 稳定排序）。扣减账本记录逐批分配，业务撤销返还归原批次；原批已过期仍过期，不能返还成新有效批次。余额、冻结、消费、过期、撤销分别记录；账户总余额不能代替某订单可退余额，其他订单积分不得拿来抵该单已耗积分。

### POL-07 人工退款审批与资金状态

**功能名称：** 独立退款单、双人审批与实际出款确认。

**逻辑说明：** 建议退款单关联原订单、原支付流水及权益来源链，支持部分/剩余权益终止退与金额为 0 的权益撤销。线上优先原路退款（当前无退款接口）；线下填写收款信息与凭证，由申请/审批/人工出款双人复核，禁止同人自批自付。审批通过≠退款到账；仅渠道成功回执或人工出款证据经复核后标成功，审批页面显示处理中、失败和到账时刻。

每笔 refundId 为幂等键，金额、对象及申请快照不可被重试改写；累计成功退款+处理中预留金额≤原实付，等价地本次可申请≤原实付−已成功退−其他处理中预留。失败释放金额与积分预留；未知/处理中保留预留并查单，不能盲目重付。拒绝无出款，成功后不可直接改回失败。赠送/0 元订单只能撤销未耗权益，无现金退款；不以修改原 orders.status 实现会员或退款状态。

### POL-08 积分包部分退款

**功能名称：** 按原实付分摊购买积分退款。

**逻辑说明：** 原购买积分数 Q、原实付 P，净单价 u=P/Q（保留高精度，赠送不分现金）；剩余可退未消费未过期购买积分 q 的退款额=roundHalfUp(q×u,2)，扣除已预留分配并受原支付可退金额上限约束。多次部分退累计金额不得超 P；最后一次可退积分清零时，在剩余可退现金上限内结清分舍入尾差。附赠按本次退购买积分/Q 的比例追回可用未耗赠品，累计追回向下取整到整数积分，最后一次全退结清赠送尾数；已耗赠品风险转人工审批，不负余额追扣、不转罚金。

申请受理时锁住具体购买/赠送批次积分与现金额度，防止消费竞态；退款失败解锁，成功后扣减原批次并写退款账本。过期包默认不自动退，可由人工按原因、支付与消费证据例外审查；不能为了退款恢复已过期积分或自动给到全额。Q=0 或来源缺失不能套公式，转人工。

### POL-09 会员剩余权益终止退与升级退款

**功能名称：** 会员保守双上限及付款链分摊。

**逻辑说明：** 建议商业公式（待 PM 确认，非法律承诺）：可退=min(P×remainingRatio, P×max(0,1−C/T))，最终按分四舍五入并受支付退款剩余额度约束。P 为本段实付净额，remainingRatio 按原始完整段 start/end 与申请冻结时刻求剩余比例；T 为该订单快照承诺的全部付费套餐积分（含未来未发），C 为该订单/合并升级段已消费的付费套餐积分，赠送不计现金基数。C 不含未来未发额度，已过期未耗也不算已消费。无积分或尚未发生任何发放时，积分上限取 P，不能除 0；T 不可确定（如未来按月额度未快照）则转人工，不猜总量。

不推荐“未消费已发/已发总量”的分母：它会把尚未发放的未来权益排除，导致过低退款。T 必须冻结在订单快照，升级后保留原支付及升级各项付费权益映射，不能拿账户余额或赠送积分代入。已退款部分应按剩余未退款价值和权益重新计算，不重复分摊。

首期推荐积分包可部分退、会员只支持“剩余权益终止退”；它不是原订单全原款退款，已经消费/经过的服务扣除后可能仅退部分现金。退款成功即终止该单剩余会员段、撤销未发任务及对应未耗积分；会员期赠送跟随失效，固定赠送按订单关联撤销未耗部分，已耗不负扣。其他未来已付款段保持原 start/end，不自动提前，空档回免费，用户可另申请提前生效。

首期默认不开放会员部分权益退款；专项审批若允许部分退，须关联清晰权益变更方案，建议只按未用时长截短，退款成功缩短 end，不得保持相同等级/期限白用；复杂情况转人工专项，不让客服只改现金。升级退款以合并后的本段价值与原始付款链统一算上限，按各原支付当前可退净额比例分摊、各笔原路退并处理分尾差，不允许旧单+升级单双退。回退等级、终止时刻及队列必须展示，不自动续回被替代的旧权益。多笔出款部分失败时保留原冻结与逐笔状态、人工处理差异，不能宣称整单成功或放开权益继续消费。

### POL-10 交易决策矩阵与状态流程

**功能名称：** 购买决策与退款状态可核查。

**逻辑说明：** 以下为建议状态，与现订单三状态分离。

| 当前状态/动作 | 建议结果 | 确认重点 |
|---|---|---|
| 免费/过期且无队列→购买会员 | 支付后立即生效 | 等级、起止、首次发分 |
| 有效同级→续费 | 无队列顺延，有队列排尾 | 完整排期、无提前发分 |
| 高级有效→买低级 | 预约降级，队尾生效 | 不降当前档、不抵高档余额 |
| 低级有效→升高级 | 等效同期限即时升级 | 补差、保留 end、回落日期 |
| 不同周期/终身/无等价价→升级 | 人工专项报价 | 不自动比例折算 |
