## 2. 后台功能清单（登录 + 15 个业务菜单）

后台技术基线为Vue3 + Element Plus + vue-router(hash) + localStorage Mock；顶栏已移除DEMO/API徽标，实际数据模式仍有提示。完整逐功能字段、默认、前置/操作/期望仍保存在原型的全部180个PN和104个TC中；本文按当前事实汇总，旧断言与本轮冲突处已修订，不以删改编号替代回归。

### 2.1 登录与会话

- 登录、登出、刷新恢复、redirect、Mock TTL 2 小时；菜单/按钮/路由与接口双端授权。
- 请求捕获 token + 会话版本；跨标签页登录/退出使旧身份、旧页面实例与在途响应失效，旧 `/auth/me` 或旧 401 不覆盖/清除新会话。身份未就绪时阻止业务请求。
- 网络恢复失败保留 token，显示加载失败与重试，身份成功后才判 403；受保护导航、窗口回焦与权限广播重新校验；管理员/角色变更后刷新当前权限。
- 默认落地从实际路由菜单元数据生成，覆盖仅 `role:manage` 等单一权限账号，零页面权限进入 403。

### 2.2 工作概览（dashboard:view）

- 用户/订单/已支付订单金额/对话指标、7 日趋势、套餐分布、专家会话量、最近用户/订单。
- 当前趋势来自本地现存记录，无伪随机补数；仍非生产数据。刷新仅接收最新响应，loading 随当前请求；失败可重试，有旧成功数据时明确保留。

### 2.3 用户管理（user:view / user:ban / user:entitlement）

- 手机号/ID、状态、注册日期筛选分页；详情 6 Tab：资料、权益、订单、对话统计、对话记录、登录日志。
- 详情读取及权益保存固定目标 ID 和请求序号，切换/关闭使旧响应失效；保存要求详情 ID 与目标一致，载荷独立复制；失败可重试，无覆盖显示“无个体覆盖，使用套餐权益”。
- 列表顶层与详情plan中返回 `membership:{source:'MOCK',status:ACTIVE|EXPIRED|NONE|LIFETIME|UNKNOWN,expiresAt,isLifetime}`，共用五态展示；只有显式 LIFETIME 显示长期有效，NONE 无会员、UNKNOWN 期限未知。
- `PUT /users/{id}/status {banned:boolean,reason}`：同用 user:ban，原因 trim 后必填且≤200字，重复状态409。封禁记录冻结区间；解封按已记录冻结时长顺延原尚有效会员期限，审计 user.ban/user.unban；冻结中拒绝权益调整与新订单。

### 2.4 订单管理（order:view / order:create / order:gift / order:remark / order:price / order:export）

- 订单号、用户ID、PENDING/PAID/CLOSED、WECHAT/ALIPAY/OFFLINE、下单日期筛选；详情含支付流水，备注审计。
- 默认关键列：订单号、用户（手机号/昵称+ID）、商品、状态、应付/成交金额、来源、操作；列设置可选到期、积分、时长、消耗、商品/优惠金额、支付/下单时间、备注。详情/XLSX 保留完整字段及支付渠道，不随可选列删减。
- 改价仅线上待支付且无支付流水、未付订单，独立 order:price；输入新应付价与必填原因≤200字，0～商品金额、两位小数且须改变。服务端校验 expectedAmount，冲突409；商品金额不变，优惠=商品金额−应付，审计前后金额与原因。**v21 增强：待支付单带 quoteExpireAt 报价有效期（种子自创建起30分钟演示口径），过期后改价409"报价已过期，请关闭重下"（规则场景24）；改价原因同时落订单本体 priceChangeReason，详情抽屉展示"本订单经过改价"告警与原因，导出新增"改价原因"列。真实渠道预下单/二维码作废重建、0元履约待交易服务**。
- 手工单：按手机号+启用 NORMAL；积分置灰，服务端读取套餐 credits，忽略客户端 credits；金额须显式非负有限数且最多两位小数，null/空串/缺失/三位小数拒绝，显式0允许。**v21 新增计费周期选择（默认月付；年付须套餐已配置年付周期价，按钮置禁用并提示；年付 durationDays=365、套餐名追加"（年付）"）与首购价申报（套餐配置了对应周期/月付基础首购价时出现勾选项，按首购价结算并在备注与审计中记录申报；未配置时后端422）。首购资格真实核定仍待交易服务。**仅 Mock 产生 PAID/OFFLINE 记录与成功流水，不代表真实收款。
- **v21 订单模型新增 orderCategory 购买动作类型**（FIRST_PURCHASE/RENEW/UPGRADE/SWITCH/PACK，对应规则 v0.2 §08 首购/续费/升级/切换/增购）：线上种子与手工单已写入，详情展示"购买动作"，导出含"购买动作"列；历史订单缺省。**契约预留 paidPriceSnapshot（实付价快照，场景33促销补差依赖）与 queuedEffectiveAt（未来期排队，场景32依赖），待交易服务接入后启用。**
- 运营特批赠送：同时要求 order:create + order:gift，赠送套餐 GIFT；remark 为必填特批原因≤200字，积分非负安全整数；金额全0、无支付流水，订单标记 creditBatchType=OPS_EXCEPTION，审计原因与类型。这只是订单分类，尚无真实积分批次。
- 赠送时长：长期固定0月；自定义默认 ceil(durationDays/30)、1–36月可调；MEMBERSHIP 固定 durationMonths=null，服务端取会员源，NONE/EXPIRED/UNKNOWN 拒绝422，ACTIVE/LIFETIME允许；不是普通购买赠分。
- 新手工单保存精确 durationDays，paidAt 加天数求 expiresAt；有天数快照优先显示天数（1天即1天），历史仅月数保留。赠送按实际日历月，月底收敛，长期 expiresAt=null。
- 非会员模式订单：PENDING/CLOSED为未生效；明确长期标志+null期限为长期；有限期以每分钟统一时钟显示未到期/已到期N天，相等已到期0天；缺失/非法期限为—。MEMBERSHIP 的状态/期限由当前模拟会员源每次查询产生，和用户五态共用展示；时长字段仍标“会员期内有效”。
- 单一会员源为持久化 MockUser.membershipExpireAt + membershipIsLifetime + 付费计划；null不推断终身，冻结区间用于恢复。历史演示回填仅补缺字段，保留已有null/期限，不依注册日期临时重算；会员源变化须重新查列表/详情/导出。
- XLSX：按筛选全部命中，单表“订单列表”，21列顺序保持：订单号、用户ID、手机号、微信昵称、套餐、来源、购买动作、到期状态、剩余积分、套餐时长、近7日消耗、商品金额、优惠金额、实付金额、状态、改价原因、支付时间、下单时间、到期时间、支付渠道、备注。文本保留前导零/公式样式原文但不生成公式，金额数值两位、计数整数，日期完整秒级文本，空表仍有表头；一次导出固定now。
- 创建手工/特批订单仍**不回写用户会员、到期或积分权益**（TC-39）；退款状态/接口/入口已移除。

## 8. 已拍板购买、会员与账号规则（2026-11-07）

本节取代原POL待确认建议及其人工退款、预约取消退款、跨周期一律转人工等冲突算例。依据 `memory/2026-11-07.md` 最后拍板记录，34个独立前台场景是后续验收参考，**当前仓库没有实现或复验这34个真实交易场景**。以下为确定规则，服务实现边界另列。

### POL-01 商品与账号
标准版 / 高级版 / 旗舰版功能一致，仅每月积分额度不同；无团队、席位和主子账号。v19 Mock迁移三档展示，旧免费档停售保留引用、历史订单/版本不改写；通用配置表单并非三档限制的真实交易校验。

### POL-02 同级续费与预约降级
无有效会员时付款后生效；同级续费接续，降级与年转月到期切换。已付未来期按队列排队接续，价格锁定付款时快照，不提前发分，不因后续改价重算。确认页须明确生效日与不退款。

### POL-03 实付抵扣与月转年
同周期升级按原实付价折算剩余价值（促销9.9按9.9，不能按标价抵扣），补差负数取0。月→年可即时转换，抵扣旧月剩余价值，自转换日按365天重置年付锚点；当天发新档首月积分，旧月批次保留至原到期日。已有已付未来期不再拦截转换，应锁价顺延排队；不能保留旧“禁止转换”结论。

### POL-04 积分包
仅有效会员账号可购买；付费积分365天有效，不随会员到期清零，会员断档后剩余有效付费积分可继续使用；不改变会员等级/期限。固定包按商品价，自定义按quantity=min+n×step且≤max、统一单价乘积分按分四舍五入。后台滑块是配置预览，不是购买接口。

### POL-05 发分与注册赠分
常规赠分仅注册100分一批，购买不另赠促销积分；年付按生效月周期发分，未来期不预发。会员期赠送旧R9动态跟随仅保留为有权运营特批管理能力，不新增常规赠送产品。批次到期/升级补发须由真实账本实施，不能用当前余额模拟证明完成。

### POL-06 运营例外
保留订单运营特批，独立order:gift并结合order:create、必填原因、审计、OPS_EXCEPTION分类；反馈奖励当前沿feedback:manage并须采纳说明，不是购买赠分。当前均无真实积分批次入账，不能把记录等同积分到账。

### POL-07 不退款
当期、年付中途退订、积分包及未来已付期一律不退款；本版不恢复退款申请、审批、出款、退款状态或旧部分退款公式。未来期唯一去向为按已拍板规则排队生效。

### POL-08 手动续费与提醒
首版无自动续费；到期即断档，到期前7天提醒。Mock commerceRules只是规则标记，未接真实提醒调度。

### POL-09 注销与封禁
注销为账户删除，积分、会员、未来期全清并二次确认；封禁与注销不同，禁止登录提示“您的账号异常，无法登录！有疑问请联系客服”，数据冻结、解封恢复。当前仅Mock冻结区间/会员期限恢复，真实跨端账号和资产服务未接，解封UI仍缺。

### POL-10 优惠券
按后台后续规则，本版不实现、不展示优惠券；不新增折券/退款状态或工具入口。

### POL-11 权威交易边界
需要服务端权威报价、实付归属与价格快照、会员段和未来期版本锁、支付回调幂等、积分发放/消费账本、账号冻结恢复、提醒任务。`PRORATED`、commerceRules或PAID演示记录均不能替代上述引擎。

### POL-12 购买确认
确认明细须展示当前档/周期/期限、实付抵扣、补差（含明确0）、转换后新锚点、完整锁价队列与顺延日、到账/下次发分和到期规则、不退款/无自动续费。当前后台只有规则说明和配置，未实现C端真实购买确认闭环。

### POL-13 场景基线
保留次日续费、降级排队、月年切换、促销实付、负差0、月末/闰年、年付逐月发分、积分包独立到期、重复回调、注销/封禁等未来联调场景；旧退款EX算例撤销，不再作为待确认政策或测试预期。

### POL-14 落实状态
规则已拍板，不再等待PM重选政策。已完成的是本地页面说明、部分表单约束、Mock迁移/接口记录及文档；真实交易服务未接。当前写接口规则、解封UI和奖励分类遗漏见R02，另行补实现和联调证据后才能宣称闭环。
